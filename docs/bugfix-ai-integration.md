- 기존 코스 장소 추가·교체·삭제와 이동시간·총시간 재계산.
- 지역·날짜 변경 시 재생성 및 이전 축제 기준점 재검증.
- 축제 운영시간과 관광지·음식점 휴무 정보 연결.
- 날짜·좌표·페이지 검증, 정렬 별칭 및 최신순 정렬 수정.
- 행사 조회 API 불필요한 keyword 제거와 외부 오류 응답 처리.

- 대기 안내 및 5분 클라이언트 타임아웃. 요청 이력을 서버 허용량에 맞춰 제한.

- DB 초기화를 import와 분리하고 반복 실행 시 upsert.
- 설치·실행 안내 및 환경변수 예시 정리.

## 검증

- Python unittest 32개 통과. 외부 API/LLM은 회귀 테스트에서 mock으로 분리.
- 프론트 API 테스트 5개 통과, oxlint 및 Vite production build 통과.
- pip check: 의존성 충돌 없음.
- 실제 TourAPI·카카오 기반 강릉 반나절 코스 생성: 3곳, 221분, estimated=false. 실행 약 0.72초(LLM 제외).
- 실제 코스 마지막 장소 삭제 및 재계산: 2곳, 약 0.24초(LLM 제외).
- 브라우저에서 홈, 강원 권역 카카오 지도/축제 마커, 강릉커피축제 상세 표시 확인.

## 실제 AI 통합 검증

- Ollama 0.40.11과 gemma4:e4b 설치 및 실행 완료. 다운로드 약 9.5GB.
- 해당 런타임에서 JSON 강제출력 요청이 501을 반환하여, 명시적인 structured-output 미지원에 한해서만 동일 모델의 일반 출력으로 재시도한다. 응답은 JSON 검증을 거친다.
- 조건 추출에 reasoning=False, num_predict=1024 적용. 수정 요청이 생각 토큰만 생성하다 잘리는 문제를 해결했다.
- 실제 `/api/chat` 생성: HTTP 200, 강릉 반나절 3곳/221분, 측정 3.0초.
- 최종 실제 `/api/chat` 수정: HTTP 200, 마지막 장소 삭제 후 2곳, 측정 0.91초.
- 브라우저에서도 자연어 생성→코스 상세→마지막 장소 삭제→2곳/158분/수정 0회 남음까지 확인했다.
- 시간은 이 컴퓨터·당시 모델 상태에서의 단일 관측값이다. 첫 모델 로드, 기기 성능, API 응답에 따라 달라진다.
- 실행 중인 로컬 서버: http://localhost:8000, Ollama: http://localhost:11434. 재부팅 후 실행은 README 참고.

## 남는 제품 범위

축제 DB는 고정 스냅샷이며 자동 갱신되지 않는다. 추천은 조건 추출 LLM + 거리·시간 규칙이고 RAG/최적 경로 보장은 아니다. 운영시간은 안내용이다. 대화 영구저장·로그인·서버 일일 사용량 제한은 이번 통합 범위에 포함되지 않는다.

초기 구현 점검 보고서는 수정 이전 상태를 기록한 이력이다. 현재 상태는 이 문서와 README를 기준으로 확인한다.
